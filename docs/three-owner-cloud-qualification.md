# Fixed three-owner CLOUD qualification

This is an inactive, bounded qualification path for three synthetic owners on
separate production MyEve deployments. It does not enable general Work, public
signup, Rooms, native execution or publication.

Each source deployment has one exact owner/client binding in a fixed roster.
Factory requires both a separate application credential and verified production
workload identity. Proof credentials are distinct. These bindings do not create
Work authority: each attempt still requires its independently approved immutable
envelope and operator-installed, one-use Factory grant.

Only the selected Work can expose a Factory start proposal to the authenticated
primary Sofie conversation. The Action Gateway checks the exact owner, Work,
version, generation and production target. Ordinary engineering discovery stays
disabled. Sofie verifies the approved configuration before reserving or dispatching
any model operation. Expiry during asynchronous checks cannot extend the original
deadline. Expired productive authority does not prevent owner cleanup/readback.

Migration 0084 adds one fixed accounting class without changing historical 0074
bytes or allocations: at most two Sofie calls within $0.30 and three Factory
operations within $1.00, including its protected completion reserve. The total is
$1.30 per owner, one candidate and at most 180 seconds. UNKNOWN retains exposure
and prevents retry/fallback. Unused allowances cannot move between owners.

Factory migration 010 allows only the three fixed client namespaces. Existing
personal installation markers, limits and history remain unchanged. Durable
admission ownership prevents roster reassignment from transferring historical
Result, evidence, read or stop authority.

Qualification includes real disposable PostgreSQL lineage, accounting,
preparation and grant transactions; all six owner substitutions; evidence lookup
denials; exact migration replay; retained personal history; revocation; expiry;
and model dispatch deadline races. Test providers are local stubs. These tests
do not establish live three-owner CLOUD execution or external-alpha readiness.

Installation is explicit operator work, never a build/request migration. Live
trust, credentials, schema installation and paid execution require their exact
separate approval. Full production evidence and identifiers remain private.
