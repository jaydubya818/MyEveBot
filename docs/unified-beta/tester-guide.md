# Unified MyEve beta: first session

Prepared for the platform owner and two separately enrolled testers. Send this guide with each person's verified private URLs only after the operator completes installation qualification. Source tests and a sample journey are not an invitation or activation.

## Before starting

Your onboarding note contains your MyEve URL, MissionControl URL, workspace name, approved project, activation window, spending limits and support contact. Use your own sign-in. Each person has a separate installation and account boundary; another tester's Work, decisions, tasks and reports must not appear.

The beta's supported app is Alpha Tasks: add tasks, edit their titles and priorities, and mark them done. Sofie can help with the same task operations. The first Factory project is bounded by the approved installation profile. Creating or saving a plan does not start execution.

## One Mission from plan to app

1. Open MyEve and sign in. Check the workspace identity before opening **Sofie**. Ask Sofie to prepare the approved project and its existing Work for the selected Mission. Keep using that Work and Mission throughout the session.
2. Open the matching Mission in MissionControl. Review its plan and Work. In **Installed Work authorization**, compare the Work reference and displayed cost and duration limits. Choose **Approve this Work binding** only for the assignment you intend. Approval alone does not reserve money or start the Factory.
3. Return to Sofie and ask it to start the approved Work. The current capability settings, owner authority, budget and backend checks must all pass. If it is refused, read the reason; do not create replacement Work to evade a limit or recovery hold.
4. Follow the same Work in MyEve. Relay activity records delegations where Relay was used; a recorded admission proof alone does not mean a delegated task ran. Open Result and Proof when they arrive. A completed producer run, independent verification, cleanup, accounting settlement and your acceptance are separate facts.
5. In MissionControl, **Refresh verified Factory evidence** reads the original correlated result. An expired observation needs a refresh. Report mismatched Work, Mission or candidate references before installing anything.
6. Once the operator has qualified the exact private candidate and runtime, open **Apps**, then the installed task-app page. Select **Preview release 1**, then **Review installation**. Read the decision and choose **Install release 1 privately** or **Decline release**. A preview uses empty temporary data; it does not alter your saved tasks. Sofie can prepare the decision, but you approve installation.
7. Add a task, change its priority and mark it done. Ask Sofie to make another task change and confirm that the app shows it. Refresh the page and confirm your saved tasks remain.

## Updates and rollback

An available update appears as another release. Preview it and approve its installation. Your saved tasks remain. To return to a previously installed release, select **Prepare rollback to release …**, then preview and approve the newly prepared release. Rollback preserves task data and app history; it does not rewind the database or refund Factory spending.

**Pause app** stops new task operations while keeping saved data. **Enable app** requires current authorization and no unresolved operation. Capability controls may separately deny new work even when the app is enabled. Revoking a Work binding requests a fence; backend cleanup is complete only when its confirmation says so.

## When something fails

- If your session expires, sign in again and reopen the existing Work or app.
- After a lost response, use **Retry same request**. It retains the original request so the committed change is not duplicated.
- If an app says recovery is required, leave it paused and report the problem. Saved tasks remain visible when the read service is available. Repeated requests cannot clear the hold.
- The external-tester policy lasts 120 hours from activation. Policy or enrollment expiry, a changed Work, revoked authority, or unresolved owner accounting can stop previews, installations and task changes. Ask the operator to investigate; a retry does not extend the window or spending allowance.
- UNKNOWN spending or cleanup is unresolved. Do not assume a timeout means that no execution happened or no money was reserved.

Open **Beta feedback** at `/feedback`, choose the affected platform and impact, and describe the steps, expected behavior and actual result. Include the Work reference when applicable. Keep passwords, tokens and financial credentials out of reports. A saved report gets a private reference and appears in your workspace history. The operator tracks reproduction, fixes and verification there.

## First-session checks

Complete one small task before requesting more features. Confirm the same Mission/Work identity across MyEve and MissionControl, your own task data after refresh, explicit approval for installation, a data-preserving update and rollback, a denied operation after pausing, and a successfully saved feedback report. The operator records the outcome for each of the three installations; another person's successful session does not qualify yours.
