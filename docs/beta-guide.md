# MyEve design partner guide

Open **Today** for a summary of work, results, decisions, blockers, and the Daily
Brief. The primary navigation is Today, Work, Sofie, Knowledge, and Apps.

1. Choose **New work**. Describe a useful outcome, what would make it successful,
   and any context or boundaries. One small assignment is enough.
2. Save the draft. This does not start execution. Choose **Plan this with Sofie**
   to review a conversation draft with the saved Work reference already included.
3. Send the draft when ready. Sofie can clarify the criteria and propose a plan
   using the existing goal tools. Actual model/tool execution depends on the
   capabilities configured for your environment.
4. Use **Needs you** to review exact-action approvals and work exceptions. Read
   the scope, recipient/resource, effects, and expiry before allowing or declining.
   A saved decision is not a confirmation that the action executed.
5. Open **Results**, then **Proof of Work**. Inspect reported checks, artifacts,
   evidence references, and limitations. A successful result is not automatically
   independently verified.
6. Choose **Useful** or **Needs improvement** to save feedback on that result.
   **Correct this** opens a draft carrying the result, Work and evidence references;
   add what needs changing before sending it.
7. Read the **Daily Brief** for its stated period. It includes completed work,
   recommended next steps, results, approaching commitments, decisions and risks.
   Scheduled routines and Knowledge changes currently have separate sources.

Knowledge lets you inspect retained context. Apps opens existing connection
management. Files, detailed planning, weekly review, settings and operational
tools remain available as secondary destinations.

If a service fails, the page names the unavailable information. Refresh to retry.
If your session expires, sign in again. Work that failed or paused retains its
context; discuss a safe next step rather than assuming retry is already underway.

## Safe product preview

`/beta-preview` uses clearly labeled synthetic data. **Try a new owner** empties
only the preview; **Load example journey** restores its examples. Preview feedback
and decisions stay in this browser tab. They never contact a model, execute work,
send a message, change a live approval, or modify the live account.

The preview demonstrates delegation wording, decisions, result evidence and
feedback. It is not a demonstration of a working Factory/Relay backend. Exiting
preview returns to live contract reads; sample records never fall back into live
empty or error states.

## Current design-partner boundary

This is a qualified UI over stable APIs plus an explicit sample journey. Production
execution, durable database integration, MyFactory/Relay delegation and protected
verification need qualification with their owning workstreams before this complete
experience can be called ready for an unattended design-partner beta.
