# Digital Worker beta integration boundary

Current authority: [canonical beta integration dossier](../verification/beta-integration/README.md).

The beta composition creates canonical WorkStore intents from qualified Goal Tasks and binds them atomically by owner and correlation key. It does not admit or dispatch an executor. An Awaiting admission state is intentional and cannot be presented as running. Results are immutable, proof-validated, owner/version/generation/criteria-bound, and carry explicit LOCAL_FIXTURE provenance in local qualification. Changed Work or newer evidence pauses stale completion and retains history.

Work Knowledge correction, retrieval/context receipts and governed learning use the frozen Recall contracts. A receipt proves context was offered; it does not prove a live Sofie model consumed it. Cross-Work selection remains denied unless a trusted policy explicitly authorizes it. Learning selects registered presentation guidance, never grants authority.

Inbox owner responses preserve exact action binding and generations through durable Goal continuation. Execution approvals and external signal hosts remain pending. MyFactory/Q37 and Capsules must be integrated only from explicitly supplied final frozen candidates.

The origin/main migration chain and active Digital Worker chain differ before 0041. The beta candidate's 0058–0061 allocations avoid occupied numbers, but this does not make the two deployment ledgers interchangeable. Preserve applied bytes and reconcile ledger provenance before merging or deploying.
