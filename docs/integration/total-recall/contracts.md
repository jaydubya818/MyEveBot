# Memory and Learning consumer contracts (v1)

**Integration contracts qualified; live runtime NOT_RUN.** Source schemas and exported types in `apps/eve/lib/total-recall/` are authoritative. No DTO field is an execution permission.

## Work retrieval and Sofie context

`WorkRecallStore(authenticatedWorkStore, selectionPolicy).retrieve(request)` takes `WorkRecallRequest` from `retrieval-contract.ts`: contractVersion 1, ownerId, workId/version, exact canonical repository/objective, projectId null, context query/purpose (`answer` or `plan`)/Work type/reference, explicit selected Knowledge identities with source Work IDs and selected owner Memory IDs, and limits. Work types are research/implementation/review; the authenticated caller binds the type, never a recalled statement or model request. Project tenancy is intentionally rejected until its own binding is qualified.

Maximum selections: 20 Knowledge roots and 20 private owner Memory roots. Maximum output: 12 items and 16,000 JavaScript characters, with caller-selected lexical relevance threshold at least 0.1. The query is at most 500 characters. Canonical Work owner, repository, revision and objective must match before retrieval; Work revision is rechecked after assembly. Candidate scans are capped at 200 records per store (201 causes failure) and correction traversal at 50 steps. A budget too small for the complete advisory envelope fails, rather than silently truncating source provenance. Character bounds are not token or UTF-8 byte budgets; the host must charge the final message against its existing token budget.

Current-Work Knowledge is available within that Work. Cross-Work Knowledge requires a separate `RecallSelectionPolicy.authorize` result for the exact authenticated owner, target Work, repository and selected identities. Source Works must have that owner and repository. Private owner Memory requires explicit selection and remains PRIVATE. The default policy denies all cross-Work/private selections. Host construction must read selection from an authenticated owner action or canonical selection record and compare exact sets; never construct an allow-all policy from model-produced request JSON. In the fixture, a distinct trusted selection snapshot crosses the process boundary separately from the request. This is not a new persistent selection store.

Explicit selection follows corrections only within the selected owner's same-Work lineage (owner scope for private Memory). Outputs preserve identity, kind, original scope and privacy, confidence, lexical relevance, correction predecessor/successor, source IDs/references/hashes/origin/relation and why-used text. Superseded and stale records are excluded. Explicit conflicts and low confidence are labeled CONFLICTING/UNCERTAIN, never promoted to Current Truth. Duplicate statement+scope+truth+provenance is injected once; differing sources remain distinct. Unsafe source references/instruction-like/credential-shaped content are excluded. The filter is defense in depth, not a universal secret or semantic-conflict detector. `authorityGrants` is always empty and trust is EVIDENCE_ONLY.

`assembleSofieRecall(recall, request, learning?)` returns `SofieRecallContext`: a bounded **user-role** JSON evidence message, item/source references, versioned learning, final message digest and attribution. Supply it as a separate user-role message through the canonical runtime's existing context API. Do not concatenate it into system/developer instructions, agent capabilities, Work readiness or policy. Recheck current authority at every existing action boundary. The adapter is labeled INTEGRATION_FIXTURE; changing that label is not qualification. `consumeRecallFixture(context, expectedCurrentStatements)` parses the actual serialized message and compares facts against independent expected values, with no model/tool call.

Learning retrieval creates an offered-guidance receipt before final delivery. A receipt does not prove the model saw or used it; assembly can subsequently fail its budget/revision check. Record the final successful assembly attribution in canonical context history, then distinguish actual response/Result use and owner acceptance.

## Result feedback and lifecycle

`LearningRuntime.feedback({feedback, resultHash})` reads an immutable native Result through `canonicalResultReader`: authenticated owner, canonical Work ID/version, stored Proof of Work schema and recomputed canonical digest must agree. Factory-produced Results already retained in canonical native custody use the same reader without calling Factory, verification or publication. Missing or mismatched Results fail closed. The fixture inserts a synthetic canonical Result only in its disposable DB; it does not claim real execution.

Feedback identifies event UUID, Work revision/type, feedback category, target=result and original Result UUID, bounded note, registered behavior and WORK/REPOSITORY scope. The persisted evidence reference binds Result ID and SHA-256; no proof prose becomes learned instructions. `/api/learning` accepts this through `operation: result_feedback` plus `resultHash`. Generic `operation: feedback` rejects target=result. Other target types remain explicitly owner claims unless a future target-specific verifier is added; the existing owner UI uses Work feedback. All endpoints remain authenticated, same-origin, bounded and qualification-only, with hosted production denied.

`LearningRuntime.decide({workId,workVersion,workType,familyId,revision,command})` checks Work/repository/scope and commits with Work-version binding and family revision CAS. Commands carry an event UUID, exact candidate version/hash, action evaluate/promote/reject/rollback and reason. Evaluation is code-owned; clients cannot submit PASS. Only fixed `cite_sources`/`state_uncertainty` behavior IDs produce advisory prose. Evidence text cannot become a new prompt, Skill, procedure, policy or tool permission.

`replacesVersion` proposes a qualified improvement while keeping the old version active until promotion. Promotion retains the predecessor as SUPERSEDED. Explicit rollback with `restoreVersion` restores only the named predecessor with its original hash and exact passing evaluation. A `correctionOf` immediately withdraws wrong guidance; no rollback may restore a version targeted by an owner correction. Rejected or failed candidates are never retrieved. Conflicting active Work/repository behaviors inject neither. Immutable past usage remains after rollback.

## Beta Product Experience

Read `MemoryProjection` and `LearningProjection` from `projections.ts`. `projectMemory` exposes remembered statement, source/origin/hash, original privacy/scope, truth/confidence/relevance, predecessor/successor and optional successful context identity/hash/reason. `projectLearning` exposes behavior and fixed guidance, status, evaluation baseline/learned scores, source feedback/provenance, correction/replacement links, permitted action availability and optional exact version/context usage with applicability reason. Usage parameters must come from owner-filtered retained receipts, not an untrusted UI submission. The projection validates the referenced version/hash; it is not a receipt lookup API or proof of successful use.

UI consumers show loading, empty, unavailable and error states separately. No schema gate failure is an empty memory list. Show correction history and uncertainty explicitly; display rejected/rolled-back versions as history. Render text escaped; turn source references into links only after the UI's safe-protocol validation. Fixed action flags are display hints, never authorization. Submit decisions back through authenticated exact-revision/hash services and reload on conflict. This branch does not edit the Beta worktree or claim its UI is wired to these new projections.

## Portable Sofie

`portableMemoryRecord(item, learningVersion?)` returns `PortableMemoryRepresentation`: contractVersion 1, type MEMORY_REPRESENTATION, immutable source identity/kind/text/owner, scope, PRIVATE or WORK_SCOPED classification, provenance, Current Truth/supersession, confidence, optional exact learning family/version/hash, source RecallItem digest, `portability.eligible=false`, and empty authority grants. The digest identifies the source RecallItem, not a signed export manifest; the Capsule owner must hash/sign its own final envelope.

PRIVATE is not SHAREABLE. There is no shareable value or implied portability consent in this contract. Owner selection, canonical source export policy, destination scope checks and Capsule qualification are separate prerequisites. Work/repository restrictions must never be flattened into owner scope. A learning version reference alone is not activation evidence: resolve its exact canonical scope/status/hash/evaluation. Historical, conflicting and corrected records remain labeled; export does not make them current. Corporate or unqualified project records are not represented.

The independent Capsule worktree's observed `lib/capsules/total-recall-adapter.ts` accepts this v1 representation and fails closed on shape/scope drift. This branch provides no Capsule storage, import, export, activation or consent implementation and does not modify that worktree. That workstream owns its own tests, classification and activation decisions.
