An already admitted `DEEP_AGENT` route backed by the native Sofie harness can now open one owner-scoped native draft. The agent-facing `engineering_direct` tool uses the authenticated Work selected in the current primary-Agent web-chat turn, a same-turn context receipt, and the persisted Agent binding. Its arguments cannot choose another Work, owner, Agent, route, source revision, verifier result, or publication target. The tool permits read-only inspection after a pause; edits require the current Work version, generation, control, criteria revision, route writer, deadline, approved profile hash, and exact draft revision.

`engineering_direct_workspaces` retains the approved base snapshot, plan, edited files, frozen candidates, and protected evidence across a fresh store/process. It admits edits only to `profile.allowedPaths`, rejects dot-path writes and likely credentials, bounds source size, and uses compare-and-swap revisions. Candidate material and Git commit identity are recomputed before custody. Submission only requests separate verification; there is no tool operation that inserts evidence, marks Work Ready, publishes, merges, or deploys. The server-owned driver claims an exact candidate with a durable lease before it can call `verifyRequested`; the evidence write checks that lease again in SQL. Evidence must match the frozen candidate, base, criteria, profile, attempt, environment, protected producer, and artifact hash. A failed check permits a new edit and candidate; unchanged candidate bytes cannot be resubmitted as a fresh attempt.
