# ER2 isolated harness boundary spike — 2026-09-26

**Verdict: ADAPT / ER2 NOT QUALIFIED.** This is an executable boundary experiment, not a Deep Agents provider run or an admitted Sofie Work route. The code is confined to `apps/eve/lib/digital-worker/experimental-harness-boundary.ts`; no production caller or default route uses it.

The candidate harness receives only two frozen model-facing functions: `readFile` and `writeFile`. Files are a bounded in-memory projection supplied by MyEve, with exact path allowlists; no host filesystem, shell, publisher credentials, MCP, Memory, Knowledge, or Relay handle is passed. Reads and writes require a fresh caller-supplied Work/generation authority check; writes additionally require a unique operation ID and expected workspace revision. The host retains a separate checkpoint/stop/candidate view. The checkpoint can be held outside the process and restored for the same Work revision and generation. The candidate is only a hash and changed-path preview; it is not an independently verified or durable Result.
