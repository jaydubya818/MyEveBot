# UI verification — 2026-11-02

Base: `9d223990fd61c63d18c078089e18c6ceb5212e4f` from current GitHub main.

Reproduced and corrected:

- Sending proceeded while conversation storage failed. Sending now waits for
  a successful owner-scoped save. Failure retains the draft and attachments,
  shows an actionable error, and starts no model session. Pending saves block
  repeated submission. Retry uses the same prerequisite.
- The composer accepted text during reconnect, then discarded it when the
  restored conversation remounted. The composer now waits for restoration and
  displays its loading state. Unsent text is retained in owner-scoped session
  storage for that conversation, surviving reload and the restore remount in
  the same browser tab. Sending stores an empty draft and deleting the thread
  removes its draft. This does not serialize pending file bytes across reload.
- Neon 1.2 adds `application_name` to its database URL. The local test adapter
  accepts that metadata and keeps all database identity checks. Eight regression
  cases cover acceptance and denied host, port, database, credential, and option
  changes, including configured query options that could override the pool host.
- Six Jev transport assertions used an older SDK wire format. They now assert
  the installed Gateway's `/v4/ai/decision-model` route and text `stateParts`.
  Runtime classification, privacy checks, and provider behavior are unchanged.

Independent read-only source review on November 3 found that files and late
dictation or edits could change the composer during the save wait. File intake
now reports that it must wait, voice input stops before saving, late speech
events cannot alter the pending message, and message actions wait for save/upload.
Retry also rejects an in-flight upload. Save/upload activity prevents background
server refresh from remounting the conversation during preparation.
The final review found attachment removal and slash-command selection were also
available during that wait; both now follow the same frozen-composer boundary.
An actual HTTP negative exposed Eve's synthetic local principal fallback in
authenticated dogfood mode. That fallback is now unavailable whenever owner
authentication is required, preserving normal unauthenticated local tooling.
Real PostgreSQL checks using a browser-created conversation denied another
owner's reads, metadata replacement and deletion, preserving the original row.
