# Post-alpha backlog

These items do not block the bounded two-person private alpha when the supported paths and concrete deployment prerequisites pass.

| Gap | Alpha treatment | Later work |
| --- | --- | --- |
| Enterprise identity and billing classification | Owner-controlled configuration; finite reviewed accounting and hard stops retained | Enterprise service identities and broader billing proof |
| Capsule scoped learning portability | Exact source version/provenance retained inertly; no scope flattening or activation | Wire format for complete canonical scope, learning hash and destination evaluation |
| Skill/Role/Pack activation | Staging only, no execution eligibility or grants | Independent destination qualification |
| Cross-person Capsules | Explicitly unsupported; each person keeps private data | A separately designed source-sharing/consent contract |
| Semantic conflicts beyond stable source meanings | Existing exact-key conflicts keep destination; import does not overwrite existing rows | Broader semantic correction review |
| Large/opaque/binary Capsule content | Bounded text-only limits and fail-closed parsing | Additional separately qualified formats and scaling |
| Exhaustive provider and recovery matrices | Relevant local concurrency/restart paths covered; live status remains honest | More providers and adversarial process-loss combinations |
| Wider multi-user hosting | Existing single-owner deployment boundary | Multi-user authentication and operational scaling if needed |
| Full release Proof/Ready | Local Results stay PARTIAL until actual canonical evidence establishes completion | Publication/CI/review/acceptance integration as required by future release workflow |

Never defer owner isolation, canonical Work admission, hard spend limits, single-writer/dispatch fencing, independent verification, migration integrity, Current Truth, or authority exclusion. A missing qualified producer source is a concrete dependency, not an enterprise-hardening item.
